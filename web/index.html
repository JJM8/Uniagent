This list is exactly the objects in LLM_PROVIDERS in .env and nothing else, so an empty list stays empty. Any of them can be renamed, repointed, re-keyed, re-wired, re-pictured or deleted, and what a provider says here is what the next request uses.

A provider's name is what you pick on the models tab, what /model takes, and what a cron job or a subagent can be pointed at - so renaming one here renames it everywhere, and anything still pinned to the old name falls back to the default. The same company can appear as many times as you like: two DeepSeek keys, a work one and a personal one, are simply two providers.

wire is the protocol the endpoint speaks, not the company running it. Nearly everything third-party serves OpenAI's /chat/completions, so openai is the answer unless you know otherwise. The scheduled jobs the cron watcher runs, straight from cron.json. The watcher re-reads that file every ~30s, so a save here needs no restart. Every job appears under cron in the chats panel, and gets a chat as soon as it is written, before it has ever run.
A schedule is two numbers, both unix seconds: start, the moment of the first run, and interval, the gap between runs. Runs land on start, start+interval, start+2×interval, and so on. An empty every box means the job happens once, at its start, and never again. A schedule that has already gone past is never caught up, so a daily job written at 9am first fires at its time tomorrow. An interval is a fixed number of seconds, so a daily job lands an hour out after the clocks change until its start is moved back.

Each RUN is its own chat, kept in chats/cron/<job>/<nnn>/. The job opens on its newest run - that run and anything you have said since - so a follow-up question carries on where the run left off without dragging last week's runs along with it. The runs before it are under history on the job's row, still there to open and read.

safety per job: off opts that job out of the check, and its own safety prompt (which must contain {call}) puts it under gentler rules than the safety tab's. A job that says neither follows the safety tab, as before. Nobody is watching when a job runs - a flagged call is denied rather than asked about, and an unchecked job runs whatever it decides to, unattended.

This is how the agent is kept out of its own code: add the files it must not edit by itself (main.py, tool_processor.py, tool_validation.py, provider.py, settings.py, command_processor.py). A blocked call stops and asks you, exactly like one the model flagged - it's not a refusal, it's an approval you have to give in person. Case doesn't matter, and blank rows are ignored.
Python reads its code once when a process starts, so editing a .py file changes nothing until that process is restarted. Settings and everything under context/ are re-read as they change, so those never need this.
The server serves this page - restarting it drops any turn running right now, and the page reconnects on its own. The cron watcher is a separate process; restarting it clears each job's remembered conversation. main.py is shared, so an edit to it means both.
